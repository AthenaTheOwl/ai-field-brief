# Lens: Adoption Action

Identify practical adoption candidates.

Use canonical action surface ids from
`config/action_surface_taxonomy.yaml`.

Each action must include a test plan, expected benefit, risk, effort, and disposition.
Do not force an action when the source is merely interesting.

Read `prompts/editorial_contract.md`. A proposed benefit remains a
hypothesis. Name a baseline, observable outcome, cost and stopping
condition before recommending wider use. Keep required permission and
rollback beside an action with side effects.
